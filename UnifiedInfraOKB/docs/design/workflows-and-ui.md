# 专家工作流、知识工作台与多来源 AI 设计

日期：2026-11-16。状态：待实现设计；需求基线见 [requirements.md](requirements.md)。
本文规定预期行为和后续演示方法，不代表已有页面、接口、模型接入或可运行系统。
字段名用于解释语义；K01 须统一字段字典、状态枚举、错误码和 API，不能据本文另建不兼容协议。

## 1 建设边界与源码事实

后端在同仓库新增独立 Go 模块 UnifiedInfraOKB，服务与提取 worker 分进程。
知识正文、修订、审核、来源与发布元数据以独立 MySQL 知识数据库为权威；原件和大对象另存。
前端沿用 UnifiedInfraWeb 的 Vue 3、TypeScript、Element Plus 及已有视觉、分页、加载和错误呈现方式。
当前源码仅有同步管理及拓扑相关前端，没有知识管理页面、知识 API client 或可复用的登录页面。
`src/App.vue` 用本地 section 切换，显示“本地环境 · 无登录”；不能假定已有路由或身份会话。
`src/api/inventory.ts` 固定 `/v1/inventory`、`credentials: omit` 和 JSON Content-Type，不可直接充当知识或上传 client。
`src/main.ts` 显式注册 Element Plus 组件；新增组件需按入口规则注册，并核对依赖清单。
需新增知识导航、知识 client、上传流程、身份接入、动作权限和独立状态；这里复用的是框架和交互设计。
知识工作台不得使用或修改 `TopologyDetails.vue`，不得依赖拓扑 DTO、实体枚举、资产选择或实际连接。
进入知识入口不应触发 `useManagement` 的来源加载；CMDB 或拓扑不可用不能阻断知识操作。
第一期不提供根因自动判定、设备关联或执行设备操作；GPU、HCA、PCIe 等仅为知识领域概念。

## 2 五个独立工作区

| 工作区 | 核心页面与用户产出 |
| --- | --- |
| 资料库 | 原件登记、上传/导入、版本与解析记录、片段定位；产出可引用的资料版本 |
| 主题研究 | 问题清单、范围、资料集、提取任务、原文与候选对照、覆盖矩阵；产出组装草稿与缺口 |
| 知识编辑 | 三类知识列表和专家表单、候选接纳、修订及来源；产出可提交审核的确定修订 |
| 审核与发布 | 冻结修订审核、发布预检、包清单、启用、回退、撤回；产出可追溯决策与发布包 |
| 已发布查询与历史 | 当前启用包查询、断言出处、修订差异、来源影响；产出带固定版本的查询结果 |

每区显示当前身份、动作权限、对象 ID 和状态；研究覆盖、修订审核与发布状态分开呈现。
知识编辑可按种类、状态、适用产品/版本、主题筛选；正式查询默认只使用启用发布包。
列表的空、加载中、失败、无权限与无结果状态分别显示，不用空数组掩盖服务故障。
对象详情应可恢复到确定 ID；K07 决定路由/URL 方案和刷新恢复，不沿用易失 section 冒充分享链接。
草稿正文必须由后端持久化；本地缓存只做未保存提示，不能作为权威存储。
页面关闭或切换对象时取消前端请求并校验响应所属对象，防止晚到响应改写当前画面。

## 3 资料登记、解析与片段

1. 专家登记标题、发布方、官方 URL、标称版本、采集时间、来源谱系和访问限制，再导入原件。
2. 上传展示服务端配置的大小/格式限制；失败提供错误码和请求 ID，不擅自扩展支持范围。
3. 第一期开启有文本层 PDF、HTML、人工文本；扫描 PDF/OCR 未实现时明确“未支持/需人工处理”。
4. URL 导入须由服务端按 K01 约定的地址与网络策略执行；保留采集快照，不能只保存会变化的链接。
5. 原件摘要用于解释重复：同一内容复用已有版本或提示重复关联，不能制造额外独立依据。
6. 新内容创建新原件版本；解析器或参数更新创建新解析版本，二者都不覆盖历史。
7. 解析页展示阶段、失败原因、文本预览和版本关系；空文本不得标成成功提取。
8. 片段绑定原件版本及解析版本，记录页码/章节/段落/字符范围、摘录和摘要。
9. PDF 可按页定位；HTML 用真实章节、段落或字符范围，不能编造页号；人工文本也有版本和范围。
10. 原件、片段和解析结果受读取权限控制；引用中的访问失败与正文被更正/证伪分别记录。

片段预览保留上下文及定位方式；文本规范化改变偏移时须有映射，不能把规范化偏移当原文偏移。
引用旧解析版本的修订仍能打开原文；禁止删除被知识、发布包或审计引用的原件和定位对象。

## 4 从主题问题到多来源组装

建议演示主题“GPU 经 PCIe 不可达”：范围限定产品/版本，问题分别覆盖定义、告警、原因及传播条件。
主题保存整理目标、范围、待回答问题、目标知识类型、确定的资料版本清单和既有知识上下文版本。
问题可逐项绑定资料、原子陈述和草稿断言；主题不是自动推理任务，也不是单份文档摘要。

1. 专家先列问题与不适用范围，选择多份确定版本的资料，并查看转载和重复来源提示。
2. 对每份资料建立完整覆盖计划：章节/页/字符范围分块，记录预期、完成、失败、跳过及理由。
3. 提取遍历计划中的全部范围；长文分块后做去重与跨块核对，遗漏或失败区间保留在覆盖清单。
4. 每份资料仅产出其实际支持的原子陈述，带条件、来源片段、明示/推导性质及待确认事项。
5. 原子陈述按问题归组，保留原文措辞、适用产品/版本、支持与反驳关系，再与既有知识对照。
6. 组装阶段把多个陈述映射到一个或多个知识草稿；每个重要断言有独立出处，不以整篇文档作笼统背书。
7. 差异先按机型、版本、条件并存；不能把“某版本如此”改写成所有版本均成立。
8. 缺口和冲突经专家决定补查、补资料、补经验、缩小用途或暂缓；模型不得自行消除冲突。
9. 提出 A→B 与 B→C 的组合链时，新增待核实推导及两边依赖，不能继承单边已批准状态。
10. 研究结论记录未穷尽的候选原因及已知缺口；部分内容可在准入规则允许的明确用途下提交。

| 问题覆盖状态 | 必须保留的事实 |
| --- | --- |
| 未检索 | 尚未执行的范围及计划 |
| 已检索未找到 | 实际检索范围、方法、时间与零结果，不能写成“已否定” |
| 支撑不足 | 已有陈述及仍缺的条件、证据或验证 |
| 已有支撑 | 满足本问题要求的断言和来源，仍不等于审核通过 |
| 冲突 | 各方陈述、适用范围、版本及待定处理 |
| 明确否定 | 否定对象、条件和直接证据 |
| 不适用 | 不适用范围及专家理由 |

覆盖矩阵采用“问题 × 资料版本”，支持下钻完成范围与原子陈述；禁止用模型自评分宣布主题完整。
资料完整提取与 RAG 补查分开记录：Top-K 返回值只说明检索命中，不能证明全文无遗漏。
补查记录查询词/精确编码、元数据条件、检索方式、索引或资料范围、结果、空结果及后续决定。
新增资料后单独建立提取记录，再更新组装草稿和覆盖矩阵；不能静默改写已经冻结的修订。

## 5 AI 任务、尝试和人工等待

创建任务时冻结输入资料/解析版本、范围清单、主题问题、既有知识上下文、提示词及输出 Schema 版本。
记录模型配置标识及提供者，但密钥仅在服务端；模型输出、原文和日志始终作为数据处理。
模型和 OpenSPG/KAG 通过可插拔适配器接入；都不是第一期必装服务，不默认调用外部模型。
无模型配置时页面明确显示提取不可用，仍可登记资料、人工录入、编辑、审核和查询既有知识。
固定响应/假模型支持离线验收；不能把假模型结果标成真实服务结果，也不能在本轮调用模型。

| 对象 | 状态与动作语义 |
| --- | --- |
| 提取 job | queued/running/succeeded/failed/canceled；重试保留历史且启用新的执行代次 |
| attempt | 每次领取的执行代次、租约、心跳、输入摘要、原始输出、校验结果和终止原因 |
| 人工处理 | 候选待处理、处理完成或部分处理；与 worker 的运行状态分离，不占租约 |

上述状态由 K01 最终冻结拼写；提取成功仅表示本次输出通过约定校验，不表示知识正确。
worker 领取、续租及写入结果都携带执行代次；仅当前有效代次可写最终结果和可接纳候选。
取消使旧代次失效；重试创建新 attempt；旧响应即使晚到也只能保留为隔离的历史诊断。
租约过期后旧 worker 不得恢复写入；取消请求与任务真实终态分开显示，避免前端提前宣布成功取消。
原始响应与解析后的候选分别存储；Schema 不合法、范围未覆盖或校验失败不能伪装为成功候选。
列表展示输入范围、完成范围、失败区间、attempt 历史与脱敏错误；断网后可按 job ID 恢复查看。

## 6 候选对照与断言来源

研究工作台左侧固定原文与定位，右侧展示候选字段，中间选择问题、候选、片段与版本差异。
每个候选显示原始输出、编辑后内容、待确认项、相似知识、冲突提示及校验结果；提示不能代替专家决定。
候选类型 candidate_kind 区分 assertion 与 knowledge_draft；原子陈述是组装材料，不是第四类正式知识。
assertion 接纳仅进入主题材料集；knowledge_draft 明确三类 kind 之一且经校验后，才能创建 knowledge_revision 草稿。
候选处理状态建议为 pending/accepted/rejected，不能用 accepted 表示知识已批准。
断言来源至少可追到 `claim → fragment → parsing version → document version`，并附相关提取批次。
出处区分提供者（模型生成/专家撰写等）与依据性质（原文明示/推导/专家经验），二者不可互相推断。
每条出处另记支持/反驳关系、核验结论及审核状态；模型生成可有直接依据，专家撰写也可能待核验。
模型提供的 fragment ID、摘录和字段支撑需服务端校验；文本相似不能证明断言被原文支持。
无原文的经验标明真实提供者、经验范围及验证缺口，不伪造片段；能否发布取决于用途及准入规则。
引用的具体断言被编辑后标记待重新核对；不能保留已通过的引用标记掩盖语义变化。

| 专家动作 | 结果与沿革 |
| --- | --- |
| 接纳 | assertion 进入组装材料；明确 kind 的 knowledge_draft 生成知识草稿；保留去向，不批准、不发布 |
| 编辑 | 保存专家修改与理由，保留原始候选；更新后重新校验出处 |
| 拆分 | 一个候选分为多份材料或知识草稿，分别迁移断言与出处；未明确 kind 时不建知识修订 |
| 合并 | 多个候选组装为材料或知识草稿，保留候选映射、范围差异和冲突决定；明确 kind 后才建修订 |
| 驳回 | 保存候选、真实决定人和理由，不删原始输出，不产生正式知识 |

接纳请求带稳定幂等标识与目标版本条件；同一请求重试返回同一结果，不重复创建知识或修订。
候选与材料/修订允许多对多；拆分/合并不能以“已处理”单值丢失去向，重复操作应能定位原结果。

## 7 三套专家表单

所有表单共享稳定 knowledge_id、确定 revision_id/修订号、标题、范围、出处、提供者、状态及变更理由。
适用资源使用领域概念，不从拓扑枚举复制；所有依赖选择确定修订，界面显示编码、版本和审核状态。

| 表单 | 核心字段及约束 |
| --- | --- |
| 异常类型 anomaly_type | 稳定编码、定义、适用资源概念、典型表现、判别条件、排除条件；定义与条件逐断言引用 |
| 告警映射 alert_mapping | 厂商/产品、事件码或规则、版本等 signature；多个候选异常及各自条件、支持和反证，不强选唯一原因 |
| 可能传播 causal_rule | 源/目标异常、可能机制、条件、时间约束、支持和反证要求、条件未知时处理；“可能”不得改成必然 |

映射候选及规则两端引用具体 anomaly_type_revision_id；缺失、无效或范围不兼容时阻止提交并定位字段。
候选集合可标为未穷尽；未知适用条件显式保留，不能填默认值伪造完整性。
传播规则必须展示抽象连接/因果前提及不适用范围；不表示实际资产间存在对应关系。
规则准入未满足时只能按允许的参考用途处理，不能成为自动判断依据；K01 明确各用途阻断项。
保存草稿可保留未完成字段；提交审核执行类型约束、引用真实性、依赖、范围和出处校验。

## 8 编辑并发、冻结与动作权限

编辑器读取正文及并发版本；保存必须提交读取时的版本条件，过期返回明确冲突，不静默覆盖。
冲突页保留本地输入，展示服务端最新版本和字段差异，允许专家重新对齐后保存，不能自动强推。
提交审核冻结正文、断言出处、依赖上下文和内容摘要；审核只能针对该 revision_id 与摘要执行。
提交后的修改或退回修订产生新 revision，保留 predecessor 和变更原因；旧审核决定不沿用到新摘要。
修订状态建议 draft/in_review/approved/rejected；被退回的 rejected 修订保留，后续修改另建 draft。
提交按钮重试、审核决定和发布动作均须按 K01 幂等契约处理，前端禁用按钮不替代服务端控制。

| 动作权限 | 可执行动作 |
| --- | --- |
| 资料管理 | 导入、登记新版本、发起解析和查看受权原文 |
| 提取与编辑 | 创建/取消/重试任务、处理候选、编辑草稿、提交审核 |
| 审核 | 对冻结修订批准或退回，记录理由和范围 |
| 发布 | 对确定批准修订预检、生成包、启用及回退 |
| 撤回 | 记录内容问题与修订撤回声明、计算依赖影响、撤回发布包并处理启用指针 |

可由同一专家持有多个权限，不预设强制双人；每个动作仍记录真实主体及当时权限判断。
前端只负责显示可用动作；后端验证身份和动作权限，不能接受任意 reviewer_id 作为身份事实。
生产身份协议由 K01/K02 确定；明确开发/测试配置才允许测试身份适配器，不能生产默认免鉴权。

## 9 审核、发布、回退与撤回

审核批准的是确定修订的内容与用途；退回附理由，待修改内容进入新修订，不原地解冻旧内容。
发布页选择已批准修订，预检依赖闭包、来源、用途准入和同 knowledge_id 只含一个修订的约束。
预检展示冲突、缺口和影响；manifest 固定知识/来源版本、依赖、Schema、校验器、评测及摘要。
先准备并校验不可变包文件，再以数据库事务及并发条件切换启用指针；文件失败不能切换。
发布生成包与启用包是不同动作；页面须展示准备中、准备失败、可启用、已启用及历史结果。
release 状态建议 building/published/failed/withdrawn；published 表示包已构建发布，不等于当前启用。
active 为独立指针及并发控制事实，不加入 release 状态；状态和动作最终由 K01 统一。
正式查询返回 release_id、修订和摘要；草稿查询使用独立入口并明确标识，不能混为正式结果。
回退是对历史包重新检查后切换启用指针，保留原包、当前包及操作者理由，不修改历史正文。
撤回是内容问题处置，记录原因、影响到的修订/依赖/包及处置结果，不能用普通回退代替。
当前包被撤回时须阻止其继续用于正式查询，选择经检查可用包或明确无可用包，不能继续返回旧内容。
withdrawn 包不得重新启用，修正后构建新包；仍为 published 的历史包若来源失效，重新评估后才允许回退。来源不可访问、更正、证伪分别生成可审查影响清单。
已发布正文与专用出处不可覆盖；修复通过新修订和新包，历史查询保留撤回/来源警示及审计链。
正式检索索引从固定发布包构建、带 release_id 和摘要且可重建；KAG 若接入也不能成为第二写入口。

## 10 A01–A14 可演示验收脚本

以下是后续实现必须演示的验收步骤，当前未执行。仅使用合成资料与固定响应；不依赖真实模型或生产系统。
准备：文本 PDF、HTML、人工文本、扫描 PDF、转载版本、差异版本；两个编辑会话及具不同动作权限的测试身份。
每场景保留对象 ID、操作记录、请求结果及页面证据；失败路径同时查看后端状态，不能只看提示框。

| ID | 操作步骤与必须看到的结果 |
| --- | --- |
| A01 | 导入同一 PDF 两次看去重解释；导入修改版并用新版解析器再解析；分别打开旧原件/旧解析片段，版本和定位仍在。 |
| A02 | 对缺少适用条件的单篇资料执行固定响应提取；只接纳有依据的陈述；草稿显示条件未知和待补缺口，不补出虚构事实。 |
| A03 | 主题关联两份互补资料并完成覆盖提取；组装一个修订；逐项点击定义、条件、机制的出处，可到各自原文及解析版本。 |
| A04 | 加入不同机型/版本及同源转载；查看差异组并尝试合并；范围差异保留，转载不使独立依据数增加，需专家作明确决定。 |
| A05 | 输入不支持字段的摘录、伪造 fragment ID 和缺失异常修订引用；分别执行校验与复核；阻断或明确待确认并定位问题字段。 |
| A06 | 对 assertion 接纳重试看材料不重复；对明确 kind 的草稿候选接纳重试看修订不重复；拆分、合并、驳回均可追查去向及理由。 |
| A07 | 两会话读取同一草稿，先后保存；后者看到冲突且输入保留；提交后改写或用不匹配摘要批准被拒绝；退回修改另建修订。 |
| A08 | 固定响应故意延迟；取消后重试并让旧响应后到；只有新代次结果有效；再注入校验失败，任务失败且无可接纳成功候选。 |
| A09 | 将未批准修订、缺依赖修订放入包看阻断；对合格包注入文件写入失败看启用指针不变；恢复后发布并核对完整 manifest。 |
| A10 | 启用第二包后回退首包，查看两包及切换历史；撤回其中内容并查依赖影响；尝试重新激活撤回包被阻断。 |
| A11 | 禁用模型并使 CMDB/拓扑接口不可用；资料与既有知识仍可编辑查询；AI 操作显示配置缺失及未覆盖区间，不伪造任务成功。 |
| A12 | 无身份/无动作权限执行写入及审核均被拒绝；同人多角色动作记录真实主体；把指令/脚本放入资料与模型响应，确认只显示为数据。 |
| A13 | 查询正式知识并保存 release_id；修改草稿后查询结果仍固定；显式查草稿有状态标签；登记来源更正可列出受影响修订及包。 |
| A14 | 从独立知识入口完成导入到查询并检查请求记录，无拓扑请求；核对 TopologyDetails.vue 无修改；报告明确区分原有同步/拓扑/空间能力。 |

交接时先冻结 K01 字典及身份、导航、上传契约，再实施资料→主题/任务→表单→审核发布；不得以本设计作为功能完成证明。
