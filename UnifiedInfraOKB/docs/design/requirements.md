# UnifiedInfraOKB 需求基线

日期：2026-11-16。版本：v0.1。状态：需求和设计文档，待实现。本轮交付目录与交接材料，不代表 API、数据库、模型服务或页面已存在。

## 1 背景与已确认方向

InfraUnifiedModel 已包含 UnifiedInfraTopology 的 Go 拓扑后端，以及 UnifiedInfraWeb 的 Vue 3、TypeScript、Element Plus 前端。本次源码核对基线为 9ffbe77635112e03a5430acbd02e829566f932de；同步、拓扑和可视化已有实现，本次未重新验证其部署环境。

用户已确认以下方向：

- 在同一 Git 仓库新增独立 UnifiedInfraOKB 后端模块，前端复用 UnifiedInfraWeb。
- 运维专家通过网页管理知识，并由大模型帮助提取草稿。
- 当前建设独立知识管理流程，不使用 TopologyDetails.vue，不接入实际拓扑或具体资产。
- 维护异常类型、告警到多个候选异常的映射、有条件的可能传播规则三类知识。
- 单份 PDF 或网页通常提供部分知识，需要围绕主题组合多来源、检查缺口及冲突。
- 知识正文和版本以独立 MySQL 知识库为权威；原件及大文件使用文件或对象存储；发布导出不可变知识包。
- 本轮先建立骨架和清楚的需求、设计、实施顺序与验收材料，后续可由其他 AI 实现。

## 2 产品目标与第一期边界

目标用户为运维专家。第一期应完成：登记资料及不可变版本，解析原文并定位片段，围绕知识主题执行 AI 提取和多来源组装，专家对照修订及复核，发布知识包，并查询已发布知识和来源历史。

第一期不实现自动故障根因判断、实际设备关联、当前或历史拓扑接入、设备操作或自动修复。知识中的 GPU、HCA、PCIe、链路等是领域概念，不能直接引用拓扑实体枚举或资产身份。适用条件可以描述抽象连接前提，不表示某条实际连接存在。

不增加知识节点或推理边到 UnifiedInfraTopology 的 NebulaGraph，不使用拓扑控制库的 sources、sync_runs、sync_rounds 或 publications 存知识内容和审核状态。不建立租户、多拓扑或作用域兼容层。

## 3 模块与存储职责

推荐沿用 Go 后端技术生态，服务与提取 worker 分进程；HTTP、业务编排、仓储和领域模型分层。具体依赖和版本由 K01/K02 任务核定并记录，不因骨架存在而宣称已初始化。

| 位置 | 权威内容与边界 |
| --- | --- |
| 独立 MySQL 知识数据库 | 文档元数据、解析记录、主题、提取任务和候选、知识修订、来源与依赖、审核、发布和操作记录 |
| 文件或私有对象存储 | 不可变原件、解析大对象、模型原始输出、发布包；数据库保留位置、摘要和生命周期 |
| Git | Schema、计算和校验代码、迁移、合成样例、设计；不作为专家知识正文的另一写入口 |
| 正式检索索引 | 由指定发布包生成，携带 release_id 和摘要，可重建，不独立修改知识 |

可以共用现有 MySQL 实例，但采用独立数据库、连接、凭据引用、迁移台账和事务上下文。UnifiedInfraTopology 的控制库契约不因此改变。OKB 本期没有 NebulaGraph 依赖。

## 4 知识类型与统一管理信息

| kind | 内容 |
| --- | --- |
| anomaly_type | 稳定编码、定义、适用资源概念、典型表现、判别与排除条件 |
| alert_mapping | 厂商、产品、事件码或告警规则及版本等 signature 条件，多个候选异常及各自条件与依据 |
| causal_rule | 源和目标异常、可能传播机制、条件、时间约束、支持和反证要求、未知时处理 |

三类知识统一保留 knowledge_id、revision_id、revision_number、标题、适用条件、来源链接、提取批次、创建与复核主体、状态、内容摘要及变更理由。稳定 ID 与修订 ID 分开；正式引用和审核不能读取一个可变化的 latest 指针。

知识提供者与依据性质分别记录。created_by_model 不表示无依据，expert_authored 也不表示已验证；断言需区分原文明示、推导或专家经验，另记支持/反驳、核验与审核结果。

## 5 资料及原文定位

支持有文本层的 PDF、HTML 和人工文本作为第一期目标格式。扫描 PDF/OCR 等未实现能力必须返回明确未支持或需要人工处理，不得以空结果冒充成功。上传大小、格式约束、URL 导入策略和错误码在 K01 契约任务明确配置与验收值。

资料身份、原件版本和解析版本分别保存。文档更新或解析器升级不覆盖旧版本。片段保留原件版本、解析批次、页码/章节/段落或字符范围、摘录及摘要；网页没有页码时使用真实结构定位，不虚构页号。

记录官方地址、发布方、标称版本、采集时间及来源谱系。采集时间不能替代文档版本。重复文件、转载和重复片段不能当作多份独立依据。来源不可访问与内容被更正/证伪是不同状态。

## 6 主题驱动的多来源知识组装

主题定义整理目标、适用范围、待回答问题及目标知识类型，例如 GPU 经 PCIe 不可达。主题关联确定的多个资料版本；单篇资料只提取它实际支持的陈述。

流程：确定问题和范围，逐资料解析与提取原子陈述，与已有知识对照，形成组装草稿，列出缺口和冲突，定向补资料或专家经验，复核并决定可发布用途。

缺口至少区分未检索、已检索未找到、支撑不足、已有支撑、冲突、明确否定和不适用。主题覆盖状态、知识审核状态与可用用途分别记录，不以模型自评分宣称主题完整。候选原因集合可标为未穷尽。

跨产品或版本差异先并存，不能无条件合并。A→B 与 B→C 的组合链若被提出，保存为待核实推导，不能继承单边审核状态。部分知识可在明确用途和已知缺口下发布；未满足规则准入要求的内容只供参考，不成为自动判断依据。

## 7 AI 提取与专家工作台

专家指定资料版本、范围及主题后创建异步任务。记录模型配置标识、提示词版本、Schema 版本、输入清单、已有知识上下文版本、每次尝试、原始输出及解析校验结果。

前端提供固定原文与候选字段对照、逐字段出处、待确认项、已有知识相似/冲突建议。专家可编辑、拆分、合并、接纳和驳回。候选原始输出保留；candidate_kind=assertion 的原子陈述接纳后只成为组装材料，candidate_kind=knowledge_draft 且明确正式 kind 的候选才可产生知识草稿修订，两者都不自动批准或发布。重复接纳必须幂等，支持多候选到多修订的关联。

提取 worker 不等待人工审核占用任务租约。任务领取、重试、取消及晚到结果须有执行代次，旧尝试不能覆盖当前结果。模型响应、日志和文档作为数据处理，不执行其指令或代码。

第一期需支持假模型/固定响应的离线验收；真实模型接入取决于获准服务配置，不默认调用外部模型。模型密钥仅由服务端管理。

## 8 编辑审核与权限

知识草稿使用并发版本检查，过期保存返回冲突，不静默覆盖。提交审核后内容、出处和依赖上下文冻结；退回或修改产生新的修订，保留沿革。

审核记录绑定 revision_id 及内容摘要，记录真实主体、决定、理由和时间。知识编辑、提取、审核、发布、回退按动作授权；可由同一专家持有多个动作权限，不预设强制双人审核。生产使用不能靠客户端填任意 reviewer_id 冒充真实身份。

复用用户身份协议需在 K01/K02 明确，OKB 独立管理知识权限和审计，不复制用户口令库，不直接读取拓扑业务表。测试身份适配器只供明确的开发/测试配置，不能成为生产免鉴权默认值。

## 9 修订依赖及发布

映射候选和传播规则引用具体 anomaly_type_revision_id。发布要求依赖闭包完整，且同一个 knowledge_id 在同一包内只有一个修订。升级异常定义不能悄悄改变旧规则含义。

发布 manifest 固定所有知识修订、依赖、来源版本、Schema、校验器及评测结果/已知缺口，并记录内容摘要。准备文件并校验成功后，再用数据库事务及并发检查切换启用指针；不能假定数据库和对象存储可原子提交。

已发布知识修订、专用内容及来源链接不可覆盖修改。默认正式查询使用启用的发布包；编辑工作台可查询草稿但必须显示状态。

回退切换到经检查可用的历史 published 包；撤回记录内容问题及依赖影响。withdrawn 包不得重新启用，修正后必须构建新包；仍为 published 的历史包遇到来源问题时，重新评估后才可回退启用。禁止删除仍被发布包或审计引用的原文/修订。

## 10 前端接入

在 UnifiedInfraWeb 增加独立知识管理入口；资料、主题整理/提取对照、三类知识、审核发布及历史查询使用独立状态和知识 API。

知识操作不依赖 CMDB 来源或拓扑加载成功。不得使用或修改 TopologyDetails.vue，不增加节点/关系上的相关知识入口，不扩展拓扑图 DTO。

沿用 Vue 3、TypeScript、Element Plus；新增组件按当前入口注册规则接入。现有请求封装固定 /v1/inventory 和 JSON Content-Type，知识接口和文件上传需单独处理。若实现分享复核链接/刷新恢复，由 K07 明确导航方案；草稿正文必须由后端持久化。

## 11 RAG 与 OpenSPG/KAG 边界

结构化提取不必经过向量检索。完整资料提取应记录覆盖范围，不能仅处理 Top-K 片段后宣称无遗漏。补查和专家查依据可以结合精确编码、关键词、元数据和语义检索，记录检索范围和结果。

OpenSPG/KAG 尚未选为必装依赖。本期可评估 Schema 约束、图文互索引等能力；若接入，正式知识索引由固定发布版本构建，不成为另一套可独立改写的权威知识。第一期不实现多跳自动根因推理。

## 12 验收场景

| ID | 必须证明的行为 |
| --- | --- |
| A01 | 相同原件重复导入有可解释去重；新版原件和新版解析分别保留，旧定位可回查 |
| A02 | 单篇不完整资料只产生有依据的候选，缺失适用条件被明确保留 |
| A03 | 多份资料可组合一个知识修订，每个重要断言可追到具体原文片段 |
| A04 | 不同机型/版本的差异不被自动合并，转载不增加独立依据数 |
| A05 | 字段出处与文本不符、伪造片段 ID、类型引用缺失可被校验或复核发现 |
| A06 | assertion 接纳不产生第四类知识，knowledge_draft 接纳重试不重复建修订；拆分/合并可追溯，驳回保留理由 |
| A07 | 两位专家并发保存产生明确冲突；提交审核后旧摘要不能被批准 |
| A08 | 取消和重试后旧模型响应不能覆盖新尝试，失败任务不变成成功候选 |
| A09 | 发布只包含已批准的确定修订，依赖闭包和来源完整，文件失败不切启用版本 |
| A10 | 回退保留历史，撤回有依赖影响，withdrawn 包拒绝重新启用；修正需生成新包 |
| A11 | 无模型或 CMDB/拓扑不可用时仍能编辑既有资料/知识，模型相关缺口明确展示 |
| A12 | 生产动作具真实身份和权限，原文与模型内容不会成为可执行命令 |
| A13 | 正式查询返回固定发布版本；草稿检索明确标识；来源更正产生影响清单 |
| A14 | 前端不调用拓扑接口，不修改 TopologyDetails.vue，三个现有拓扑模块能力未被宣称为本次新增 |

## 13 已实现状态与后续责任

本轮没有 go.mod、运行时依赖、DDL、OpenAPI、模型调用、知识 API 或知识前端。占位目录只是职责边界。详细数据模型、工作流、接手顺序和分任务验收分别见本模块 docs 中对应文件；K01 先冻结协议和字段字典，下游引用同一版本。

源接口、模型服务、文件存储与身份配置由部署条件决定。执行者可在任务权限内选择常规依赖并记录依据；影响业务语义、共享契约或数据职责的变更必须更新文档并由集成负责人协调，不自行连接生产或上传内部资料。
