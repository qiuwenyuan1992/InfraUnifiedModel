# UnifiedInfraOKB 协作与实施约束

本文件适用于 UnifiedInfraOKB 及其子目录。用户当前明确指令优先；根目录 Agents.md 的中文要求继续适用。

## 接手顺序

先读 README.md、docs/design/requirements.md，再读 storage-model.md、workflows-and-ui.md、api-boundaries.md 和被分配工作包。当前仅骨架与文档，不得宣称已有可运行应用、迁移、知识 API 或前端。

每项任务记录实际分支、基线、允许路径、消费的契约版本与验收。现有文档中的结构是设计基线；K01 负责冻结机器可校验契约，下游不私自发明字段或状态。

## 产品边界

- 这是独立运维知识管理，不是本期故障诊断或资产关联引擎。
- 不使用或修改 TopologyDetails.vue；不访问 CMDB/拓扑接口，不复用拓扑的实体枚举、来源身份值、同步任务或发布表作为知识模型。知识资料可有自己的 source_id，但属于独立来源命名空间，不引用 CMDB 来源身份。
- 不修改 UnifiedInfraTopology 的数据库、迁移、NebulaGraph Schema、同步流程及现有模型。
- 不增加租户、多拓扑、作用域兼容层。知识主题是整理问题及资料的业务对象，不是资产隔离域。
- 三种正式 kind 固定为 anomaly_type、alert_mapping、causal_rule。原子陈述是候选/组装材料，不是第四类正式知识。
- 专家网页维护正文，AI 仅生成候选与辅助建议；接纳、复核、发布分别记录。
- 明确原文明示、推导和经验；创建者是模型或专家，与依据是否充分分别记录。
- 完整度、审核状态与允许用途分别管理；禁止为补齐模板捏造事实、引用或概率。

## 代码与存储边界

- 使用独立 Go module，独立 server/worker 入口；具体初始化属于 K02，本轮未创建 go.mod。
- 优先使用独立 MySQL 知识数据库；独立连接、迁移台账和事务上下文，不把知识正文放入拓扑控制库。
- 文件/对象存储保留原件、解析大对象、模型原始输出和发布包；数据库保存不可变引用、摘要和状态。
- Git 保存代码、Schema、设计和合成样例，不保存真实资料正文、生产案例、凭据、模型输出或运行数据。
- handler 不直接访问数据库或调用模型；service 组织业务流程；repository 管数据一致性；document/extractor/storage 为可替换适配。
- 可变条件采用受 Schema 约束的 JSON 或结构化字段，不执行配置、文档或模型中的任意脚本。
- OpenSPG/KAG、向量检索、OCR、Python 服务和额外基础设施需要明确任务和评估，不默认为前置条件。
- 模型服务和身份服务通过适配器与配置接入；默认开发验收可使用明确标识的假模型，不声称已验证真实服务。

## 版本与正确性

- 文档原件版本、解析版本、知识修订、提取尝试和发布版本分开。
- 稳定 knowledge_id 与 revision_id 分开；引用固定异常修订，不能在正式发布中隐式读取 latest。
- 草稿采用乐观并发检查；提交审核后内容、来源及依赖冻结，修改新建修订。
- 审核绑定具体修订及内容摘要，审批后变化必须重新审核。
- 单包内同一条目只有一个修订，依赖闭包、来源和 Schema 必须完整。
- 发布文件先准备和校验，再以数据库事务和并发检查切换启用指针，不假设文件存储与 MySQL 能原子提交。
- 候选接纳和任务执行幂等；取消/过期尝试的晚到响应不可覆盖当前状态。
- 发布、回退、撤回分开；withdrawn 包不得重新启用，修正后构建新包。保留被历史版本引用的知识和资料，撤回影响必须可追溯。
- 资料/正式知识检索分开过滤版本，草稿必须明确标识，不把索引变成第二权威写入口。

## 身份与信息边界

服务端识别真实操作主体，分别检查读取、编辑、提取、审核、发布和回退权限；不信任客户端传入的 reviewer_id。可以同人拥有多个动作权限，不强制增加双人审核。测试身份不能成为生产默认值。

不得自动连接生产数据库、实际模型、内部文档服务或设备；不得复制内部 URL、真实资产、原始案例或凭据到外部仓库。使用用户授权的环境和经过批准的数据。

## 协作与交付

- 每个并行任务使用独立 checkout/worktree，按工作包限定写入路径，不共享未提交状态。
- K01 拥有公共契约；K02 拥有 go.mod/go.sum、公共配置、依赖装配与迁移编号；K07 才能按清单修改 UnifiedInfraWeb。
- 不改动与本任务无关的文件，不擅自调整共享路径。冲突先核对归属，由集成负责人协调。
- 未来实现采用真实失败测试再实现；重点验证并发、版本、引用、取消、权限、文件与数据库提交边界。
- 文档/占位目录只检查结构和链接，不为它们编写形式化业务测试。
- 只有实际初始化后才能给出 go test/build 等运行证据；未来计划里的命令不是本轮通过结果。
- 未经当前任务明确授权不提交、推送、创建 PR 或合并。禁止强推、覆盖他人改动或跳过 hooks。
- 交付使用 docs/development/templates/handoff.md，说明实际实现、验证、未验证项、缺口及下一步。
