# 统一基础设施拓扑开发约定

**状态：** 待评审  
**日期：** 2026-09-20  
**适用范围：** `UnifiedInfraTopology`

## 1. 产品边界

- 首版仅服务一个部署实例中的单一拓扑域。
- 不设计租户、拓扑范围或兼容隔离层；不得为未来多租户预留字段、参数、索引或身份前缀。
- `source_id` 必须保留，用于区分不同 CMDB 来源、限定稳定身份和支持来源级清理。
- 当前没有生产部署和必须保留的存量数据；新基线可以直接替换旧迁移、旧图 Schema 和旧资产 API。
- 不实现旧 Schema、旧 API、旧迁移校验和或旧数据布局的兼容路径。

## 2. 权威模型

- 实体语义只来自 `docs/model/entities/`。
- 关系语义只来自 `docs/model/relationships/`。
- 当前模型固定为 10 个实体 Tag、4 个 Edge Type、11 个关系语义和 14 个合法端点组合。
- 不创建 Address、NetworkNode、TerminationPoint、占位节点或按批次复制的资产节点。
- 数字 ID 只允许用于单次采集中的引用解析，不得进入最终身份、VID、关系身份或持久化外键。
- 无法解析到稳定身份的引用不得生成节点或边；必须记录诊断。

## 3. 存储职责

### 3.1 MySQL

MySQL 只保存控制面信息：

- 数据来源配置与启停状态。
- 同步任务、领取状态、重试信息和幂等键。
- 来源游标、采集检查点和完整范围证明。
- 同步诊断、统计、开始/结束时间和发布结果。
- 当前已发布版本、图 Schema 版本和必要的写入围栏状态。

MySQL 不保存：

- 图实体属性副本。
- 图关系候选或关系快照。
- 通用实体表、来源键表或身份绑定表。
- 按同步批次复制的设备、端口、地址或关系版本表。

### 3.2 NebulaGraph

NebulaGraph 只保存当前有效拓扑：

- 10 个实体 Tag。
- 4 个领域 Edge Type。
- 当前实体和当前关系属性。
- 首次入图时间与最近完整同步见到时间。

来源历史由来源系统承担；本项目不在图中保存历史版本。

## 4. 代码边界

- `internal/model` 保存领域类型、枚举和值对象，不承担 HTTP 序列化兼容。
- `internal/adapter` 只负责来源采集与来源 DTO，不直接写 MySQL 或 NebulaGraph。
- `internal/service` 负责采集编排、归一化、引用解析、校验、诊断和发布决策。
- `internal/repository` 负责控制面事务与图读写，不决定业务关系语义。
- `pkg/nebula` 只封装 NebulaGraph 客户端能力，不包含实体或关系规则。
- API handler 不直接构造 nGQL，不直接调用来源适配器。

## 5. 实现原则

- 测试先行：先写能证明契约的失败测试，再写最小实现。
- 修复根因：不得通过兼容字段、双写、静默降级或 SQL 回退掩盖模型冲突。
- 外部值必须参数化传入查询；不得拼接来源值、用户值或身份值到 nGQL。
- 所有集合输出必须确定性排序；禁止依赖 map、数据库或来源接口的自然顺序。
- 所有身份与关系 ID 必须确定性生成；禁止随机 UUID 和写入顺序生成的 Rank。
- 来源凭据只保存引用，不得写入日志、错误、任务详情或图属性。
- 未确认的来源语义不得自行推断；保留原值并记录诊断，或阻塞受影响范围发布。

## 6. 时间与空值

- 系统生成时间统一使用 UTC、秒精度。
- 来源时间先解析为 UTC；无法证明有效的占位时间归一为 NULL。
- 空字符串、缺失和 NULL 的语义由实体文档逐字段定义，不得全局互换。
- NebulaGraph 可空属性必须显式声明 NULL；不得用零值冒充缺失值。

## 7. 测试与完成标准

每个实现任务至少满足：

1. 新增测试在实现前失败，失败原因与目标行为一致。
2. 任务专项测试通过。
3. `INVENTORY_GRAPH_TEST_CONFIG= go test ./... -count=1 -timeout=90s` 通过。
4. `go vet ./...` 通过。
5. 以下入口均可构建：
   - `go build ./cmd/server`
   - `go build ./cmd/migration`
   - `go build ./cmd/worker`
6. `git diff --check` 通过。
7. 不包含无关文件或未评审的模型变化。

需要真实 NebulaGraph 的测试必须显式启用，不得让默认单元测试依赖外部服务。

## 8. Git 与计划纪律

- 一个提交只交付一个可独立验证的任务。
- 不修改或覆盖用户的无关工作区改动。
- 不自动提交未跟踪的 `Agents.md`。
- 不修改已确认模型来迎合旧代码；应重写旧代码以符合模型。
- 实施计划中的复选框只在验证证据存在后勾选。
- 阶段完成后记录提交哈希和验证命令；下一阶段重新建立计划，不沿用旧进度。
