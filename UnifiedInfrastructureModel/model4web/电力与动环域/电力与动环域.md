# 电力与动环域：供给模型、证据映射与分析边界

## 1. 范围与证据基线
本域描述电源、配电、备用切换、设备受电与环境观测，回答“已知谁为谁供给、哪些路径可能受影响、哪些证据尚缺”。空间归属沿用[空间归属域](../空间归属域/空间归属域.md)，终端设备与电源组件沿用[计算与主机接入域](../计算与主机接入域/计算与主机接入域.md)，不另建同名资产副本。
沿用三域证据分级：S＝已核验标准语义，E＝样例记录，D＝内部设计，P＝项目目标，U＝待确认。以下实体和关系定义为 P；样例表明确标注 E/U，源设计冲突不强行选一版当事实。
当前材料有电气资产和局部线路，但没有已验证的端到端供电链，也没有足以证明 A/B 独立、备用切换成功或 N+1 容量满足的证据。

## 2. 标准适用范围
| 标准或参考 | 已核验范围 | 采用边界 |
| --- | --- | --- |
| [Modbus 官方规范入口](https://www.modbus.org/modbus-specifications) | 官方说明应用协议 V1.1b3 描述事务中的功能码；另有串行、TCP/IP 和安全协议 | S 仅限入口说明；不是电力资产、供给方向或传感器语义元模型，未逐条核验协议全文 |
| ANSI/TIA-942 | 数据中心基础设施适用范围参考，未逐条核验 | 不据此声称本系统通过等级或冗余认证 |
| DMTF CIM | 设备、组件及关联建模候选参考，类名和版本待核验 | 不将本项目 PowerTerminal、SUPPLIES 等标成标准原生类型 |
Modbus 地址、寄存器号不能脱离网关、站号、功能码及厂家点表唯一定位业务测点。量纲、倍率、有符号数、字节序、枚举和质量位必须由设备点表及契约明确，不凭寄存器数值推断开关状态。

## 3. 完整目标实体及当前覆盖
| 实体 | 语义与关键属性 | 当前覆盖 |
| --- | --- | --- |
| Substation、HighVoltageCabinet、Transformer | 变电站、高压柜、变压器；来源类型、额定参数、位置 | E：拓扑有节点及引用；部分端点身份冲突或缺失 |
| UPSGroup | UPS 的逻辑编组；组码、管理范围、配置摘要 | E：组 28；不能作为 UPSDevice 别名 |
| UPSDevice | 独立 UPS 设备；型号、容量及单位、运行状态 | E：设备 2570；容量单位与状态契约 U |
| RemotePowerPanel | 列头柜；额定参数、输入输出与位置 | E：资产 606 及拓扑 RPP 引用；不同来源 ID 需核验 |
| Circuit、Breaker、TransferSwitch、Busbar | 回路、断路器、切换开关、母线；额定参数、状态、联锁规则 | P：尚无可独立识别的完整实例证据 |
| PDU、Outlet、PowerTerminal | 柜内配电、插座及电气接线端点；设备局部编号、方向、相别 | P：机柜汇总字段不足以生成实例 |
| BatterySystem、PowerSupplyUnit | 电池系统、服务器电源模块；父设备、槽位、容量、健康 | P：有摘要，无独立组件身份或接线证据 |
| Sensor、MeasurementPoint | 传感器及测点；安装位置、量纲、采集地址、质量码 | P：缺实例、点表和被测对象映射 |
| CoolingEquipment、CoolingZone | 冷却设备及服务区域；运行模式、覆盖范围 | P：缺完整设备与覆盖关系；不是根据 Room 自动生成 |
| AlarmEvent、MetricReference | 告警事件、外部指标引用；来源、时间、状态、测点 | E：告警引用与局部告警样例；指标原始时序不复制进资产拓扑 |
| UnresolvedEndpoint | 待解析端点记录，不是已确认资产 | P：隔离未知粒度和外键，不以占位资产伪装覆盖率 |
电气资产亦使用统一实体身份。若 UPS 等设备同时出现在通用设备库存中，领域类型表示同一实体的角色或子类型；合并前须核验身份，不因为名称相同就合并。

## 4. 关系、方向与基数
| 关系 | 两端及基数 | 核心约束 |
| --- | --- | --- |
| MEMBER_OF | UPSDevice → UPSGroup，多对多能力；实际成员依契约 | 编组不是馈电；组成员数摘要不展开为设备 |
| ASSOCIATED_WITH | RemotePowerPanel → UPSGroup，多对多 | 保存业务分组关联，不冒充 UPSDevice → RPP 供给 |
| LOCATED_IN / MEMBER_OF | 电气资产 → Room / Module | 前者物理落位，后者逻辑编组；复用空间域定义 |
| HAS_COMPONENT / HAS_TERMINAL | 资产 → 组件 / PowerTerminal，1 对多 | 实例组件同时属于一个已确认父设备；端点不能用设备名称替代 |
| ELECTRICALLY_CONNECTED_TO | PowerTerminal ↔ PowerTerminal，多对多能力 | 物理接线事实，不代表当前带电或能量流向；回路 ID 区分平行连接 |
| SUPPLIES | 上游资产或端点 → 下游资产或端点，多对多 | 工程供给方向，附粒度、回路、相别、额定值、状态和证据；未核验方向不得升级 |
| SUPPLY_COVERAGE | 电气系统或设备 → Room、Row、Cabinet，多对多 | 粗粒度供电覆盖声明，不生成末端接线，也不推导区域内所有设备失电 |
| TIE_WITH | 母线或电气设备 ↔ 同类端点，多对多 | 表示联络能力；导通与切换另依开关、联锁和时态 |
| MEASURES / OBSERVED_ON | MeasurementPoint → 被测对象；AlarmEvent → 关联对象 | 测点应有明确粒度，告警可有多个候选关联并标注置信状态 |
| COOLS / MONITORS | 冷却设备 → CoolingZone；Sensor → 区域或对象 | 覆盖不等于确定温升因果；需时态、位置及运行状态 |
同一物理连接反向查询不复制事实；若采用有向图存两条邻接边，二者需指向同一连接 ID。并联、旁路和备用路径允许结构环路，但必须使用状态约束，不能套用空间树无环规则。

## 7. 动环接入、时态与分析
共享[空间域公共记录规范](../空间归属域/空间归属域.md:63)：source_ref、observed_at、ingested_at、valid_from/valid_to、evidence_level、resolution_status、schema_version。电气线路另保留端点粒度、方向状态、回路和 A/B 标签；工程连接、配置意图、当前运行状态分别存储。
测点接入先核验网关/设备/寄存器映射、量纲与倍率，再关联 Sensor、MeasurementPoint 和被测对象。温湿度、漏水、烟感、功率、电流、电压及开关状态都不能只凭指标名自动绑定到房间或设备。
指标只存外部查询引用、标签映射和聚合策略；原始时序留在监控系统。告警保留源事件 ID、发生/恢复时间、接收时间、源状态、归一状态及原文，处理重复、乱序和状态冲突；过期数据不得伪装实时状态。
影响分析按三层输出：结构上可能波及、当前条件下预计受损、运行观测已确认受损。遍历仅沿供给语义关系，不能穿过 MEMBER_OF 或 LOCATED_IN 当导电边；结果同时附路径、时间、证据和缺失条件。
A/B或N+1审计至少需要：两端完整身份、上游共同故障点、支路/开关状态、负载及额定容量、维护降额、备用切换策略、设备电源需求与末端接线。任一关键条件未知时结果为“无法确认”，不是默认通过或默认失败。
电池续航需负载、可用容量、老化、放电特性及策略；冷却失效后的温升需热负载、空气流动、热惯性和运行观测。拓扑不能单独计算确定续航、温升或业务宕机时间。
What-If 使用隔离场景版本，不修改生产事实；注明假设、数据覆盖与状态时间。任何自动处置或告警抑制还需独立安全审批，关联候选不直接当根因。

## 8. 分阶段接入与验收
阶段A：导入电气资产、分组、位置和原始线路声明，建立端点解析队列；禁止由汇总字段展开组件。阶段B：补齐回路、开关、接线端点、方向及枚举契约，形成可追溯局部供给子图。
阶段C：接入动环点表、运行状态与监控引用，补末端设备电源接线。阶段D：在覆盖率与新鲜度达标的范围内开放上游追溯、潜在影响分析、冗余审计和场景模拟；容量与性能阈值需另行约定并实测。
验收必须覆盖：组28/设备2570/组引用720不误合并；UPS拓扑510不强定型；0与冲突584不造真实设备；4200/4067到59586仅表达已知线路；行覆盖不展开确认支路；A/B标签不输出冗余已通过；空告警列表不输出健康已证实。
北向响应需携带已解析端点比例、缺失回路、未知开关状态、容量缺口、数据时间和推导等级。覆盖率分母须明确是已采集对象还是业务全量，不能用已解析子图自证全量完整。
本轮为文档及离线样例核验，未调用内部电力 API、采集 Modbus、验证现网馈电方向、运行故障模拟或复现容量与性能结果。上述实体缺口和验收项是接入计划，不是已完成实现。
