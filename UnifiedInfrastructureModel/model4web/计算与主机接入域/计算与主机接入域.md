# 计算与主机接入域：资源、组件与接入证据

## 1. 定位与边界
本域管理计算资源编组、设备组件、主机接口及到网络接入端的关联，不单独交付完整网络域。与[空间归属域](../空间归属域/空间归属域.md)共享 Device、Cabinet、Room，与[电力与动环域](../电力与动环域/电力与动环域.md)共享 PowerSupplyUnit 和受电端点；视图不同不复制资产。
证据等级沿用 S＝标准已核验语义、E＝样例直接记录、D＝内部设计、P＝项目建议、U＝待确认。本文实体、关系及接入步骤均为 P，除非明确标注其他等级；样例存在不代表已在运行系统接入。
ComputePod 是源系统的资源逻辑分组，不是 Kubernetes Pod。源接口区分管理、计算、存储和带外管理平面；查询计算平面只是其中一种视图，不代表其他平面没有对象。

## 2. 标准及网络边界
| 参考 | 已核验语义或状态 | 本域采用边界 |
| --- | --- | --- |
| [RFC 8345 §4.1、§4.4.9](https://www.rfc-editor.org/rfc/rfc8345.html#section-4.1) | S：node 在 network 内标识，同一设备可对应不同网络中的节点 | Device 是全局资产，NetworkNode 是网络作用域对象，不能直接等同 |
| [RFC 8345 §4.2、§4.4.2](https://www.rfc-editor.org/rfc/rfc8345.html#section-4.2) | S：termination-point 可代表物理或逻辑端口、接口；层间映射保持通用 | NetworkTerminationPoint 不天然等于 PhysicalPort；到资产接口的绑定由扩展明确 |
| [RFC 8345 §4.4.5、§4.4.6](https://www.rfc-editor.org/rfc/rfc8345.html#section-4.4.5) | S：link 是有向点到点，聚合或多归属可由底层链路支撑 | 一条双向物理连接不等于一条协议模型的有向 link；上下层支撑不证明实时转发路径 |
| [RFC 8345 §4.4.3、§4.4.10、§4.4.11](https://www.rfc-editor.org/rfc/rfc8345.html#section-4.4.3) | S：区分配置和运行状态；引用完整性需应用处理；标识采用 URI | 不用配置意图代替观测，不要求项目全部资产键改用网络标识 |
| [IEEE 802.1AX-2020 官方介绍](https://1.ieee802.org/tsn/802-1ax-rev/) | S限介绍：一个或多个并行全双工点到点链路可组成链路聚合，向 MAC Client 提供单链路视图；未核验完整规范 | 两个对端记录不证明 LAG、LACP 或多机聚合已经配置且运行正常 |
| IEEE 802.1AB、CDP、IEEE 802.3、ISO/IEC 11801 | 邻接发现、以太网与布线参考；本任务未做条款级核验 | 邻接缺失不证明没有接线；端口名称不是跨设备唯一标识 |
| DMTF CIM、TM Forum SID | 组件与资源模型候选参考，版本和具体类待核验 | 本文英文模型名不是标准原生类的逐字复刻 |
IEEE 802.3ad 是历史相关名称；Linux Bond 有多种模式，不能全部解释为 LACP。Bond 是逻辑接口，不是物理线缆插接点。BGP 会话是控制平面关系，Established 不保证业务可达；Overlay 关系不固定绑定单一 Underlay 路径。

## 3. 目标实体与身份
| 实体 | 定义与最小属性 | 当前证据 |
| --- | --- | --- |
| Device | 共享服务器或网络设备资产；类型、角色、来源标识、生命周期 | E：服务器535335、设备541739等 |
| ComputePod | 逻辑资源分组；来源ID、业务编码、平面、逻辑归属、楼宇覆盖 | E：POD944；设备成员契约 U |
| NetworkCard、GPU、PowerSupplyUnit | 设备内部独立组件；父设备、来源组件ID、序列号或受控局部槽位键 | P：当前主要是配置摘要，不能展开真实组件 |
| PhysicalPort | 设备或网卡上的物理接线端口；父对象、局部编号、介质和额定速率 | E：有对端端口名称；本地主机端口及完整身份 U |
| HostInterface、BondInterface | 主机网络命名空间中的接口；名称、类型、配置和运行状态 | P：缺完整接口库存、成员和状态 |
| AddressAssignment | 接口上的地址配置；地址族、地址、网络作用域、有效期 | E：设备级IP/MAC字段；接口映射 U |
| AccessObservation | 主机到候选对端的来源记录；本地对象、远端标识、端口原文、时间、解析状态 | E：server_tor_ports；不冒充完整接线 |
| NetworkNode、NetworkTerminationPoint | 网络模型中的节点及终结点；网络/节点局部作用域 | P：与 Device、HostInterface 的绑定待接入 |
| AlarmEvent、MetricReference | 共享事件与指标引用；对象粒度、来源、时间、状态和外部定位 | E：风扇及电源告警；GPU组件级映射 U |
共享 source_system、source_object_type、source_id、scope 和 entity_id。组件序列号与槽位键需确认生命周期；更换组件不因槽位不变而沿用旧实例身份。接口名称在设备及命名空间内解释，IP/MAC在网络或租户作用域和有效期内解释，不作为全局主键。

## 4. 关系、方向与基数
| 关系 | 方向与基数 | 约束 |
| --- | --- | --- |
| MEMBER_OF | Device → ComputePod，多对多能力 | 当前样例未证实成员；平面、角色和有效期参与判断，不替代物理落位 |
| ASSIGNED_TO / SITED_IN | ComputePod → LogicalDataCenter / Building，多对多能力 | 复用空间域逻辑归属与楼宇覆盖；不能把逻辑站点当物理站点 |
| HAS_COMPONENT / HAS_PORT / HAS_INTERFACE | 设备或组件 → 组件 / 物理端口 / 接口，1对多 | 实例在同一时刻有明确直接归属；组件树不循环，归属未知不虚构 |
| MAPS_TO | HostInterface → PhysicalPort，多对多能力 | 物理接口、虚拟功能等依实际契约绑定；Bond不得当物理端口 |
| AGGREGATES | BondInterface → HostInterface，1对多 | 保存模式、成员、期望与实际状态；多成员不自动证明带宽叠加或冗余 |
| HAS_ADDRESS | HostInterface → AddressAssignment，1对多 | 缺接口时只保留设备级地址声明；允许共享地址但必须明确作用域与语义 |
| PHYSICALLY_CONNECTED_TO | PhysicalPort ↔ PhysicalPort | 常规点到点连接同一时刻端点占用最多1条；分支/跳线需明确中间结构，不机械套用 |
| OBSERVED_ACCESS | Device → AccessObservation，1对多 | 观测可引用候选远端Device/PhysicalPort；本地端点未知不建确认接线 |
| REPRESENTS / MAPS_TO | NetworkNode → Device；NetworkTerminationPoint → 接口或端口 | 单设备可由多网络节点表示；聚合抽象不可强制一一对应，绑定按扩展契约 |
| OBSERVED_ON | AlarmEvent或MetricReference → Device或组件，多对多能力 | 候选关联与确认关联分开；设备级事件不强降到GPU或端口 |
逻辑成员、物理组件、物理接线、接口映射、聚合和观测六类关系分别查询。若提供设备级 CONNECTED_TO 视图，必须注明是端口接线派生还是来源单侧声明，不能隐藏证据等级差异。

## 6. 观测、时态与故障分析
沿用空间域公共身份、关系追溯、冲突、属性版本和有效时间规则。配置意图、资产库存、邻接观测与运行状态分别保留，未知观测时间不得以当前时间伪造；完整成功快照或权威删除事件才可触发失效策略。
IP关联监控必须按事件时刻查询AddressAssignment，并保留租户/网络作用域、多候选及未解析状态。不得因业务IP与带外IP同时位于设备字段中就当同一接口；缓存需版本、失效与重放策略，不能用当前归属改写历史归属。
[故障样例](../../evidence/gpu故障.md:42)实际为风扇和电源告警，portName为空、linkFaults为空，不是GPU拓扑或链路健康证明。事件文本中的IP与结构化IP不同，部分文本包含Normal但结构化状态活跃，需保留冲突并核验归一规则，告警uuid不能作为资产uuid。
GPU指标需独立GPU身份、设备关联、采样时间、单位和质量；若涉及GPU分区，还需分区生命周期与父GPU映射。设备级告警不得自动扩展为每张GPU故障，缺组件身份时只展示设备级观测。
主机双上联审计至少需要两端端口、物理连接、交换机身份、Bond模式及成员状态、聚合协商和共同故障域；业务可达性还依赖VLAN、路由、策略和实际转发。输出潜在影响、条件推断、观测确认三个等级，不用拓扑可达代替业务可达。

## 7. 接入顺序与验收
阶段A导入共享Device、ComputePod对象和原始字段，核验分页、ID/编码、平面与成员类型；阶段B接入组件、接口、作用域地址与接线，保留不完整AccessObservation；阶段C补齐Bond配置/状态、邻接和监控引用；阶段D在覆盖与新鲜度达标范围开放跨域追溯和冗余分析。
验收包括：POD944可追溯但不虚构成员；空数组不套用字符串查询；两个远端同名端口不合并；没有本地端口不生成完整接线；网卡/电源摘要不展开组件；IP复用不串设备；组件更换保留历史；告警文本冲突可见；无数据不等于健康。
北向支持按设备列组件及接口、按ComputePod列已确认成员、查看未解析接入、按时间关联监控、追溯空间与供电。响应携带证据等级、确认/候选状态、覆盖分母、时间与缺口；性能目标需按真实负载实测，不承诺秒级或任意分钟完整回溯。
本轮仅完成文档和离线样例核验，未调用内部API、运行CMDB同步、查询DCGM、验证现网LACP或执行生产故障分析；验收清单是后续准入要求，不是已通过测试的报告。
