基础设施行业标准关系图

先确定标准中“什么对象，通过什么关系，连接什么对象”。本页是类型关系参考，不是系统架构、固定工程接线、现场拓扑或合规认证。

三层分开：主视图只使用标准类及原生关系；中文业务类型与跨标准关联是项目映射；实际接线、运行状态和容量另需现场事实。箭头表示表中声明的关系方向，不自动表示电流或冷却介质流向。相同类型重复出现不代表复制资产。

测点 ≠ Sensor ≠ Observation ≠ 告警。Sensor 的可感知属性由 sosa:observes 表达，不代替某次 Observation 的 observedProperty；Actuator 不直接充当 actsOnProperty 的活动主体。

观测逐边说明 · 来源均为2017年固定版；不主张统一强制基数
编号方向与官方属性适用边界
O1 感知与活动Sensor→Observation：madeObservation；逆属性 madeBySensor。Sensor→ObservableProperty：observes。Sensor 可以是设备、人或软件；观测是活动，不能将其与传感器资产合并。
O2 观测属性Observation→ObservableProperty：observedProperty。描述本次观测估计的属性；“具备测温能力”不是“某次温度观测”。量纲、相别与测点粒度另行适配。
O3 目标对象Observation / Actuation→FeatureOfInterest：hasFeatureOfInterest；该属性也适用于 Sampling。观测对象与传感器安装位置不同；对象可映射到空间、设备、回路等，但本体不提供跨源资产匹配规则。
O4 结果活动→Result：hasResult，逆属性 isResultOf；活动→字面值：hasSimpleResult。资源结果与字面值不是同一类型的边；这里展示 Observation / Actuation 子集，不完整展开采样。结果也不自动等同告警事件。
O5 执行活动Actuator→Actuation：madeActuation，逆属性 madeByActuator。本图描述执行活动，不执行设备操作；有命令或设定值不等于执行已成功。
O6 作用属性Actuation→ActuatableProperty：actsOnProperty。主体是具体活动，不是执行器资产；改变后的实际状态需要观测或其他状态证据。
O7 过程活动→Procedure：usedProcedure。可复用的协议、工作流、算法或方法与单次活动分开；不是采集服务地址或外部指标存储位置。
O8 承载Platform→Sensor / Actuator / Sampler / Platform：hosts，逆属性 isHostedBy。承载不等于观测对象或冷却覆盖；映射到 CIM/IFC 安装关系需额外契约，不能无条件等价。
O9 对象属性FeatureOfInterest→Property：ssn:hasProperty，逆属性 ssn:isPropertyOf。属于 SSN 扩展。SOSA 的 domainIncludes/rangeIncludes 注解不等同严格 OWL domain/range 或数据库外键约束。

时间与基数：phenomenonTime 是结果适用时间（可为区间）；resultTime 是活动完成时间，不自动等于采集或入库时间。轻量 SOSA 与 SSN 附加公理分层采用；未核对机器可读本体的附加限制不写成统一 1:N 或接口必填要求。

Redfish 衔接：Circuit 1.8.1 与 CoolingLoop 1.1.0 的读数摘要若提供 DataSourceUri，可按该字段定义引用对应 ReadingType 的 Sensor。Redfish Sensor 资源与 SOSA Sensor 的等价关系仍需映射；读数摘要不自动生成完整 Observation 历史。

网络逐边说明 · RFC 8345 §4、§6；无统一强制 1:N
编号路径、方向与基数作用域和边界
N1 网络成员network/node 与 network/link 均为列表，0..*；分别由 node-id、link-id 标识。来源：§6.1 ietf-network / §6.2 ietf-network-topology。Link 是拓扑模块的增补；节点和链路身份在所属网络作用域内解析。
N2 节点终结点network/node/termination-point，0..* 列表，以 tp-id 标识。来源：§6.2。TP 身份还需 Node 作用域；其物理端口 / 逻辑接口映射不是基础模型统一规定的资产外键。
N3 链路两端link/source/source-node、source-tp；link/destination/dest-node、dest-tp。各叶子为可选单值；基础 YANG 不强制四者均出现。来源：§6.2。语义上 Link 为有向点到点；源/目的 TP 引用在对应节点内解析。可选不代表缺失引用的实例具备完整拓扑。
N4 网络支撑上层 network/supporting-network→下层 network；0..* 列表，键 network-ref。来源：§6.1。明确网络分层；不是空间包含或资产组成。
N5 节点支撑上层 node/supporting-node→下层 node；0..* 列表，键 network-ref、node-ref。来源：§6.1。保留下层网络作用域，不只存 node-id；多个支撑节点不等于多台物理设备。
N6 链路支撑上层 link/supporting-link→下层 link；0..* 列表，键 network-ref、link-ref。来源：§6.2。可表达多条下层链路支撑上层链路，不自动解释成链路聚合协议。
N7 终结点支撑上层 termination-point/supporting-termination-point→下层 TP；0..* 列表，键 network-ref、node-ref、tp-ref。来源：§6.2。不能丢弃任一作用域键；与节点及网络层间映射保持一致。

层间校验：支撑关系不得直接或传递自引用；这不是禁止网络转发拓扑存在环。引用存在性、分层一致性与无环性需分别检查，不假定一个 YANG 校验器能发现全部传递环。

三层扩展：RFC 8346 §4 增补 L3 单播拓扑属性，如节点前缀、链路度量和 TP 地址；不是完整 BGP 会话、RIB/FIB、VLAN/VXLAN 或综合网络资产模型。物理交换机、网卡、线缆复用共享资产身份，协议层对象单独适配。

六、业务映射边界：标准能表达什么，项目还需决定什么

上面五类视图不是单一标准规定的统一模型。共享资产身份连接各领域表示；映射本身须有明确规则和来源，不能因名称相同或类型相似自动合并。

业务类型的采用边界（项目层，不新增伪标准关系）
业务对象可复用的标准关系仍需项目契约 / 后置验证
列头柜、机柜 PDU配电功能采用 E1—E7；物理包及组成参考 S4；装柜参考 S3，主要空间落位参考 S2。列头柜不按中文名称自动等于 FloorPDU。明确配电资源与物理柜体的身份映射；UPS、列头柜、PDU 不强制串成固定链。
回路、断路器、切换开关、母线回路之间的供电引用参考 E3—E5；适用物理设备的端口与连接参考 E8—E9。四类对象分别建模。保护、切换、条件供给、覆盖和联络分别定义；BreakerState 不替代独立开关资产，CircuitType 不自动生成母线组件。
服务器、交换机、网卡、PSU物理组成参考 S4；机柜安装参考 S3；PSU 到电源插座采用 E6；网络表示采用 N1—N7。设备资产、机箱和功能资源并非同义。设备到网络节点、端口到 TP 显式映射；配置字符串和接口地址不足以生成真实组件或连接。
测点、内置仪表、外部指标感知、观测活动、被测属性、对象和结果采用 O1—O4；承载采用 O8。测点保存对象、相别、量纲、倍率、采集地址和有效期；可来源于内置仪表，不强造传感器资产。外部时序以引用衔接，不复制成设备实体。
告警、控制设定与执行执行器、执行活动和作用属性采用 O5—O7；IFC 专用构件控制关系见附录 R9。告警关联对象、阈值策略、设定值及命令状态单独定义。执行活动、执行成功和实际状态不等价；通用告警不强套 IFC 构件关系。
液冷、空调、冷却覆盖液冷资源与连接采用 C1—C5；安装复用 S2—S4，设备受电复用配电视图。完整空气系统、服务区域与风水管工程细化尚未展开；冷却覆盖不等于所在空间或确定故障因果。主次侧不等于供回液。
房间、行、模组、POD、UPS 组实际空间分解采用 S1，落位/附加引用采用 S2，适用逻辑成员采用 S5。先区分空间、物理结构与逻辑集合；不固定所有层级。成员、关联、供电、安装不能互相替代。

统一身份与证据：保留来源系统、源对象标识、对象类型、映射规则、有效时间与记录时间；同一资产跨视图复用身份。来源、编码、名称、IP、MAC 或同值 ID 都不是通用的全局合并依据。

后置而非阻塞项：实际接线、开关状态、容量、A/B 独立性、冗余切换、LACP、端到端可达及故障传播依赖实例证据和验证。本页交付五类核心类型关系，不声称覆盖所有基础设施标准、全部专业工程或通过合规认证。

三、两类容易混淆的关系

网络连接：网络拥有节点与链路，节点拥有终结点；一条链路是点到点且有向，转发方向为源端→目的端。标准属性引用方向为链路→源端、链路→目的端，见 N3。双向连接用两条有向链路表示；四类上下层支撑见 N4—N7，不能据此认定 LACP 已成立。
感知 / 控制：IFC 的 R9 仅连接“分配流动构件”和“分配控制构件”；通用观测与执行的标准关系见 O1—O9。P2 仅保留测点、告警及跨源对象身份的项目映射，不替代 SOSA / SSN 原生关系。

四、标准关系、端点与基数

本表“每关系实例”与“对象可参与多少关系”分开描述。标准允许缺省，不等于项目完整性要求可以省略；未知信息也不能填成已确认事实。

编号 / 语义标准端点与基数项目映射与限制
R1 空间分解
IfcRelAggregates · §5.1.3.20		每关系实例：整体 IfcObjectDefinition 1；无序部分集合 1..*。一般 Decomposes 为 0..1，但空间结构实体的 WR41 进一步要求恰有一个父分解关系，父对象为 IfcProject 或 IfcSpatialStructureElement。候选映射：物理站点→IfcSite，建筑→IfcBuilding，房间→IfcSpace；仅当实际语义吻合。空间树无环，最高层挂项目。禁止直接自引不等于自动排除间接环。项目“数据中心”若是逻辑集合，应改用编组。
R2 主要空间落位
IfcRelContainedInSpatialStructure		每关系实例：IfcSpatialElement 1；IfcProduct 集合 1..*。产品主要空间包含为 0..1。房间落位机柜、设备可参考此关系。机柜必须先映射为适当产品类型，不当作空间类。WR31 禁止用它代替空间层级分解；设备装入机柜不等于 IFC 主要空间包含。未装柜设备也可直接落位空间。
R3 机柜安装
CIM_ChassisInRack		GroupComponent：CIM_Rack；PartComponent：CIM_Chassis。已读页面未明确给出引用基数，本图不据此规定全局 1:N。仅适用于机柜—物理机箱。Device 是项目资产身份，不能无条件等同 CIM_Chassis。BottomU 是最低安装 U 位；1U=4.445cm，不定义完整安装区间、占用冲突或安装历史。
R4 包内物理组成
CIM_Container		GroupComponent：CIM_PhysicalPackage；PartComponent：CIM_PhysicalElement。引用基数未从已读页面确认。适用实体包—物理元素；不是任意逻辑组件集合。LocationWithinContainer 是包内位置，不自动形成 U 位契约。一般整体—部分也可考虑 R1，但不能将不同机制无差别合并。
R5 逻辑成员分配
IfcRelAssignsToGroup		每关系实例：IfcGroup 1；IfcObjectDefinition 集合 1..*。对象可以参与 0..* 个组分配。系统可采用 IfcSystem；POD、逻辑模组等映射为组仍是项目选择。组成员不等于物理安装、上下游馈电或独立冗余。不存在成员证据时不补造边。
R6 附加空间引用 / 服务空间
IfcRelReferencedInSpatialStructure · §5.4.3.57		每关系实例：IfcSpatialElement 1；IfcSpatialReferenceSelect 集合 1..*。SELECT 为 IfcGroup 或 IfcProduct。对象可被 0..* 个空间引用。图按系统→服务空间阅读，与标准属性列举顺序不同。可表达系统服务空间及产品附加空间引用，不是主要包含。不能用它构建一般空间层级；IfcSpace 引用例外按正式规则处理。IfcRelServicesBuildings 自 IFC 4.3.0.0 弃用，不用于新图首选。
R7 设备端口嵌套
IfcRelNests		每关系实例：整体 IfcObjectDefinition 1；有序部分列表 1..*。设备可有 0..* 个嵌套关系，端口的嵌套父关系为 0..1。官方端口用法为 IfcDistributionElement 嵌套 IfcPort。项目电气端口需按 IfcDistributionPort 等适当类映射；不能对所有 Device 无条件套用该类型。
R8 端口连接
IfcRelConnectsPorts · §5.4.3.50		每关系实例：RelatingPort 1；RelatedPort 1，均为 IfcPort；RealizingElement 可选 0..1。禁止同一端口自连。端口两个连接角色的反向基数各为 0..1，不能合并为总连接数最多一条。端口流向可双向或缺省；图中本端→对端不是供电方向结论。连接只能证明声明的连接结构，不能单独推导当前供电、容量、A/B独立性或故障影响。
R9 专用感知 / 控制
IfcRelFlowControlElements		每关系实例：IfcDistributionFlowElement 1；IfcDistributionControlElement 集合 1..*。分配流动构件与感知/控制构件之间的专用关联。不要把任意温度指标、日志、告警记录都映射成此关系；通用观测使用 O1—O9，跨源对象映射另见 P2。
R10 网络、节点、终结点与链路
RFC 8345 · §4、§6		网络下节点与链路、节点下终结点均为列表，无最少一项约束。节点身份属于网络作用域。一条链路语义上为有向点到点；基础 YANG 的源/目的节点及终结点叶子可选，不能宣称均为模式强制必填。终结点可以代表物理端口或逻辑接口，但不必等同，具体映射需增补。双向用两条有向链路；多宿主、聚合可用多条下层链路支撑上层链路。支撑链路不允许直接或传递自引用循环。意图态和运行态分开，悬空引用需修复。
P1 资产与网络视图映射项目关系：Device ↔ NetworkNode、PhysicalPort / Interface ↔ TerminationPoint。具体基数待确定。同一设备可在多个网络中拥有不同节点，不复制资产身份。RFC 基础模型不提供完整资产匹配契约；IP、MAC、名称或同值 ID 都不足以跨来源自动合并。
P2 测点、告警与跨源对象映射项目关系：测点、告警及跨源记录 ↔ 设备 / 端口 / 回路 / 空间。对象类型、作用域、映射方向和各自基数分别确认；总览只画机箱到测点的候选映射。要求来源、对象定位、有效时间及证据类型；测点、告警与观测活动是不同实体，观测活动的标准关系见 O1—O9。时间序列、告警和测点不可仅凭字符串名称直接连到资产。
P3 条件性供给项目关系：供电设备 / 回路 → 负载。无统一强制树或本轮已核验的通用基数。需要工程接线、端点流向、回路、开关状态、有效时间和证据。并联、旁路、联络可形成环，不能套用空间树无环要求；组引用不证明馈电，A/B 标记不证明独立冗余。

六、优先确认的项目选择

  1. 空间：物理站点与逻辑数据中心是否分开？行和模块分别是空间区划、实体结构还是集合？是否需要楼层层级？
  2. 安装：设备资产与物理机箱是否分开？是否保留独立安装记录，承载 U 位、占用高度和有效时间？非机柜设备如何直接落位空间？
  3. 连接：电气接线、条件性供给和系统成员是否明确分开？网络物理端口、逻辑接口与视图终结点是否分开？
  4. 观测：哪些来源能给出准确对象、端点、时间和状态？不能确认的关系保留未解析，不画成现场事实。
