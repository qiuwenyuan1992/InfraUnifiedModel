# 空间归属域：统一模型、证据映射与接入边界

## 1. 定位与结论
本域回答资产在哪里、某空间内有哪些资产、安装位置如何随时间变化。物理位置、逻辑管理归属与供电覆盖分别建模，不把管理模组强行插入物理空间树。
本文件是目标元模型与离线样例核验结果，不是生产接口验收报告。与[电力与动环域](../电力与动环域/电力与动环域.md)、[计算与主机接入域](../计算与主机接入域/计算与主机接入域.md)共享同一 Device、Cabinet、Room；不按视图复制资产。关系英文名是项目建议名，不是标准原生定义。
目标物理主链为 DataCenter → Building → Room → 可选 Row → Cabinet → Device。Module 是逻辑编组；LogicalDataCenter 是逻辑数据中心。未知的中间层保持未知，不造占位房间或虚构机柜行。

## 2. 证据分级与标准边界
三域统一分为：S＝标准已核验语义；E＝内部样例直接记录；D＝内部设计描述；P＝本项目目标建议；U＝待确认契约或证据。E 不等于现网真值，D/P 不等于已经实现。外键存在属于 E，跨来源实体等价和关系成立仍需独立核验。
| 参考 | 用途与核验状态 | 不得据此推出 |
| --- | --- | --- |
| ANSI/TIA-606-C | 标识、标签与管理体系的适用范围参考；未取得并逐条核验标准正文 | 标准强制规定本项目空间树或 CONTAINS 名称 |
| ANSI/TIA-942 | 数据中心基础设施规划参考；版本与具体条款待选定、待核验 | 样例满足等级、容量或冗余认证 |
| ISO/IEC 11801 | 通用布线参考；未做条款级映射 | U 位、行、模组均是该标准规定的固定实体层级 |
| DMTF CIM、TM Forum SID | 可作为物理资源、位置及组件建模候选参考；具体类与版本待核验 | 本文英文类型是上述标准的逐字实现 |
| RFC 8345 | 已核验网络拓扑的网络作用域、节点及终结点语义；详见计算域标准表 | 网络 node 就是全局资产 Device，或该 RFC 定义机房物理包含树 |
[目标文件](../../目标.md:34)中的强制图数据库、任意分钟完整回溯及秒级分析均视为目标或假设；元模型不绑定 Neo4j、Nebula 或其他存储。历史查询文档仅用于识别源语义，不作为数据库选型结论。

## 3. 实体定义与身份
| 实体 | 定义及最小属性 | 当前证据与边界 |
| --- | --- | --- |
| DataCenter | 物理站点；名称、站点编码、地址与来源身份 | 各空间对象有 idc/idc_id 引用；不得与逻辑数据中心混用 |
| Building | 物理楼宇；名称、楼宇编码、站点引用 | [楼宇样例](../../evidence/数据中心楼宇API.json:27)存在楼宇 2、3 |
| Room | 物理房间；名称、楼层、楼宇引用 | [房间样例](../../evidence/数据中心房间API.json:13)存在房间 4、5 |
| Row | 房间中的机柜行；行编码、房间引用 | [拓扑样例](../../evidence/power.json:482)存在行 12652；并非所有来源都有此层 |
| Cabinet | 实体机柜；编码、容量与安装位置规则 | [机柜样例](../../evidence/数据中心空间-机柜.json)与拓扑嵌套均有记录 |
| Device | 服务器、网络设备等统一资产；设备类型与资产身份 | 计算域管理组件与接口，本域只管理落位 |
| Module | 逻辑管理或供电组织单元；名称、业务编码、作用域 | [模组样例](../../evidence/数据中心模组.json:12)有实例 31、36；不当成物理容器 |
| LogicalDataCenter | 逻辑运营归属，和物理站点独立 | 楼宇及计算分组有相关引用；完整对象及契约待补 |
| RackPlacement | Device 在 Cabinet 内的一次安装记录；U 起止、正反面、槽位、有效期 | P；有 U 位字段支撑位置属性，但尚无独立安装记录接口 |
身份基线：保存 source_system、source_object_type、source_id、scope 和原始标识；分配稳定内部 entity_id。该字段集合为 P，不宣称源系统已有全局主键契约。具体编码与存储方案后置。
实例 ID、业务编码、名称、uuid、device_uuid 不互相替代。UUID 先作为来源标识保存，跨源合并需确认生成规则、唯一性和生命周期；设备 IP 与名称不能直接作为全局资产键。

## 4. 关系、方向与基数
以下为 P，约束针对同一有效时刻的规范视图；源观测允许不完整或冲突，但不能静默覆盖。
| 关系 | 方向与基数 | 规则 |
| --- | --- | --- |
| CONTAINS | DataCenter → Building、Building → Room、Room → Row，各 1 对多 | 子对象规范物理父级最多 1；必须无环 |
| CONTAINS | Room 或 Row → Cabinet，1 对多 | 有 Row 时以 Row 为直接父级；到 Room 的链路可派生。无 Row 时直挂 Room，不造 Row |
| LOCATED_IN | Device → Cabinet，或电气设备 → Room；多对一 | 表达已知粒度的物理落位，不代替组件归属；RackPlacement 保存精确 U 位 |
| MEMBER_OF | 空间或资产 → Module，多对多能力 | 当前数据若只有单值，按单值导入；跨楼宇、多成员需实际关系证据 |
| ASSIGNED_TO | Module 或计算分组 → LogicalDataCenter，多对多能力 | 逻辑管理关系，不参与物理父级唯一性检查 |
| SITED_IN | Module 或计算分组 → Building，多对多能力 | 表达声明的楼宇覆盖，不意味着物理包含；有字段才记录 |
| HAS_PLACEMENT | Device → RackPlacement，1 对多历史记录 | 同时有效的安装记录不能相互冲突；特殊跨柜设备另行定义契约 |
房间直属设备、无法确认机柜的设备只保留已知落位粒度。对已确认机柜内设备，其房间字段用于路径校验；不同时写成两个相互竞争的直接父级。
源关系 CONTAIN、CONTAINED_IN、BELONGS_TO、HAS_* 不能只按名称统一替换：先核查两端类型与业务含义，再映射至物理包含、逻辑成员或派生视图。反向浏览不是另一份事实边。

## 6. 空值、冲突与时态治理
三域公共记录字段建议为 source_system、source_object_type、source_id、scope、source_ref、observed_at、ingested_at、valid_from、valid_to、evidence_level、resolution_status、schema_version。source_ref 应能定位文件行、JSON 路径或受控接口快照。
关系还需 relation_id、from_id、to_id、relation_type、assertion_kind。assertion_kind 区分源声明、观测、派生与人工确认；resolution_status 取 resolved、unresolved、conflict。只有证据状态和解析状态都满足查询策略的边才进入确认视图。
有效时间采用左闭右开区间；未知起点保留未知，不用采集时刻伪装安装时间。observed_at 是观测时刻，ingested_at 是系统接收时刻；created_at、updated_at、last_time 的源含义需要分别核实。
记录 observed_at 不足以支持双时态查询；若需“当时知道什么”，另保存 recorded_from/recorded_to 或不可变版本日志。历史实体属性也要版本化，不能只给关系加时间便承诺完整历史回溯。
空数组、null、空字符串、0 依来源契约归一化。0 不默认有效 ID，也不在未知契约下永久丢弃；保留原值及待解析原因。含 null 的归属数组不生成成员节点。
同一资产存在多个物理父级时，保留各来源声明和冲突，不按最新写入盲选。字段权威源按对象类型和属性配置；来源可信度不能替代身份核验。名称变化更新属性，不重建身份。
迁移时关闭旧落位有效期并建立新记录；源删除、暂时缺页和采集失败区分处理。只有完整成功快照或权威删除事件才能触发失效策略，分页不完整不能清空空间树。

## 7. 安装与容量校验
U 位采用闭区间仅是当前样例支持的候选规则；实施前确认起算方向、正反面、半宽/共享槽位、设备高度以及零 U 设备。常规设备高度应等于结束位减起始位加一，且不超过有效容量。
安装冲突在同一机柜、同一有效时刻、同一面和槽位作用域内比较；不同面或零 U 设备不机械判冲突。字段不足时输出“待确认”，不要误判可安装。
机柜 rack_size=8 不可解释为 8U。used_u_num + spare_u_num = u_num 只是样例算术一致，disabled_u 是否已计入仍未知；必须区分物理空闲、禁用、预留和可分配容量。
不得依据机柜插座摘要生成独立插座或 PDU 实体；电气容量与 U 位容量各自核验，联合放置决策还需重量、功耗、散热和接入条件。

## 8. 分阶段接入与北向能力
| 阶段 | 可交付能力 | 准入条件 |
| --- | --- | --- |
| A：样例与契约 | 来源清单、类型字典、空值规则、ID/外键范围和关系别名表 | 验证分页、权限过滤、删除语义、时间字段；不能从 count 推断已读完 |
| B：基础位置 | 导入已知空间资产及落位声明，形成可追溯局部树 | 身份去重、无环、父级冲突隔离、未解析引用可见 |
| C：安装与归属 | U 位校验、逻辑模组归属、搬迁历史 | 安装位置及成员契约确定；不以电气支路替代物理位置 |
| D：跨域分析 | 空间资产清单、共同位置风险、供电与接入下钻 | 复用三域身份；结果携带覆盖率、时间窗口与缺失边界 |
北向查询建议支持按时间查位置、按空间列资产、查询待解析引用与冲突、比较两个时刻的搬迁差异。响应区分直接事实和派生路径，携带证据引用、数据新鲜度及不完整原因。
更新采用事件增量加周期对账。事件是否具备稳定 ID、乱序重放与去重条件需核验；没有事件源时先实现可靠轮询，不虚构实时能力。存储与索引待查询负载、规模和 SLA 实测后选择。

## 9. 验收清单与未决项
- 来源追溯：每个实例与关系都能回到源记录；同数值、不同对象类型的 ID 不误合并，改名不新增资产。
- 空间结构：无物理包含环；机柜直接父级唯一，Row 缺失不造节点；逻辑模组不改变物理路径。
- 样例回归：可解释局部 411/819/12652/59682 链；房间 4/5 与楼宇 3 的匹配独立保存；机柜 3661 不混接。
- 字段边界：M2 不作实例键，含 null 的数组不建边，building_full_name 的数字值不伪装已核实名称。
- 位置历史：搬迁前后可区分；未知时间明确标注；安装冲突不覆盖原始声明。历史能力仅覆盖实际保留的数据时间段。
- 容量边界：禁用、预留、空闲口径未确认时不得输出确定可用 U；不由汇总字段造组件。
- 跨域一致性：Device、Cabinet、Room 身份共享；位于同房间不能推导同供电支路或同网络故障域。
仍需业务方确认：物理站点与逻辑站点的对象契约；Module 的范围与多成员规则；各 ID/UUID 的生命周期；U 位坐标和容量口径；数据源权威优先级及删除/时态语义。
本轮仅完成文档级离线核验，未调用内部 API、运行同步、验证生产一致性或复现性能指标。上述验收清单是后续接入门槛，不表示已全部通过。
