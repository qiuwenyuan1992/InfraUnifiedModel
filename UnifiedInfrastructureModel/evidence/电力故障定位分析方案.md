# 电力故障定位分析方案

## 概述

基于已建立的物理拓扑和电力拓扑，实现精准的电力故障定位和影响分析。通过图数据库的强大查询能力，快速追踪故障传播路径，评估影响范围，并提供修复建议。

## 技术架构

```
数据采集层 → 故障检测层 → 传播分析层 → 定位决策层 → 可视化展示层
    ↓           ↓           ↓           ↓           ↓
CMDB/API    规则引擎    图算法分析    AI模型      Web界面
```

## 核心功能

### 1. 故障传播路径追踪

利用Neo4j图数据库的电力拓扑关系，实现双向故障追踪：

- **向上追溯**：从故障设备追溯到供电源头（UPS组→UPS设备→列头柜）
- **向下分析**：分析故障对下游设备的影响范围
- **横向关联**：识别同一供电路径上的相关设备

### 2. 故障影响评估

根据受影响设备数量自动评估故障严重程度：

- **轻微** (0个设备)：设备自身故障
- **一般** (1-5个设备)：局部影响
- **严重** (6-20个设备)：区域影响
- **重大** (20+个设备)：大范围影响

### 3. 故障根源定位

通过分析电力路径，自动识别故障的根本原因：

- **UPS组故障**：影响所有连接的UPS设备
- **UPS设备故障**：影响直接供电的列头柜
- **列头柜故障**：影响直接连接的机柜
- **设备自身故障**：单个设备问题

## 实现方案

### Neo4j查询策略

```cypher
// 1. 故障设备向上追溯供电路径
MATCH path = (device:Device {device_sn: $faultyDeviceSN})-[:POWER_SUPPLY*]->(source)
RETURN path

// 2. 故障设备向下分析影响范围
MATCH (faulty)-[:POWER_SUPPLY*]->(affected:Device)
WHERE faulty.device_sn = $faultyDeviceSN
RETURN affected

// 3. 同一供电路径上的所有设备
MATCH path = (source)-[:POWER_SUPPLY*]->(device:Device)
WHERE source.type IN ['UPSGroup', 'UPSDevice', 'RemotePowerPanel']
RETURN path
```

## 故障场景分析

### 1. UPS组故障场景

- **影响范围**：所有连接的UPS设备及其下游设备
- **定位方法**：检查UPS组状态，分析连接的UPS设备负载
- **修复策略**：切换到备用UPS组，检查电力输入

### 2. UPS设备故障场景

- **影响范围**：直接供电的列头柜及其下游设备
- **定位方法**：追踪UPS设备到列头柜的供电路径
- **修复策略**：启用备用UPS设备，检查UPS内部组件

### 3. 列头柜故障场景

- **影响范围**：直接连接的机柜及其内部设备
- **定位方法**：分析列头柜到机柜的电力供应关系
- **修复策略**：切换到备用列头柜，检查配电开关
