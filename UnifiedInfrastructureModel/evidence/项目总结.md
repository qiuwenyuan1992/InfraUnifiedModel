# 数据中心拓扑同步项目总结

## 项目概述

本项目完成了从数据中心到设备的完整拓扑关系建模和同步系统，包括空间拓扑、电力拓扑和网络拓扑的统一管理。

## 核心功能

### 1. 空间拓扑关系
- 数据中心 → 楼宇 → 房间 → 机柜 → 设备
- 使用 `CONTAINS` 和 `CONTAINED_IN` 关系
- 支持大规模机柜数据同步（83,653个机柜）

### 2. 电力拓扑关系
- 数据中心 → UPS组 → UPS设备 → 列头柜 → 机柜
- 使用 `HAS_UPS_GROUP`、`HAS_UPS_DEVICE`、`HAS_REMOTE_POWER_PANEL`、`POWER_SUPPLY` 关系
- 完整的电力供应链路追踪

### 3. 网络拓扑关系
- 设备间的网络连接关系
- 使用 `CONNECTED_TO` 关系，包含端口、IP等详细信息
- 支持延迟关系创建，确保实体存在后再建立关系

### 4. 设备统一建模
- 服务器和网络设备统一使用 `Device` 节点类型
- 通过 `parent_type` 区分设备类型
- 支持完整的设备属性映射

## 技术架构

### 同步顺序
1. 数据中心（DataCenter）
2. 模组（Module）
3. 楼宇（Building）
4. 房间（Room）
5. UPS组（UPSGroup）
6. UPS设备（UPSDevice）
7. 列头柜（RemotePowerPanel）
8. 机柜（Cabinet）

- 分批处理大数据量（每批200个机柜）
- 独立超时上下文（每批60秒）
- 内存使用监控

### 错误处理
- 延迟关系创建策略
- 实体不存在时跳过关系建立
- 详细的日志记录和错误追踪

## 关键实现

### 1. 数据模型
- 统一的设备模型支持服务器和网络设备
- 完整的属性映射（包括 `server_tor_ports`、`server_tor_sn`、`role`、`role_id` 等）
- 支持 `parent_type` 和 `parent_type_id` 保留

### 2. 关系建立策略
- 先同步所有实体，再建立关系
- 记录待处理关系，后续批量处理
- 确保关系建立时两端实体都已存在

### 3. 大规模数据处理
- 83,653个机柜的成功同步
- 内存使用控制在合理范围内（最大约113MB）
- 支持生产环境的大数据量处理

## 关系类型总结

| 关系类型 | 描述 | 方向 |
|---------|------|------|
| BELONGS_TO | 模组属于数据中心 | Module → DataCenter |
| CONTAINS | 空间包含关系 | 父级 → 子级 |
| HAS_UPS_GROUP | 数据中心拥有UPS组 | DataCenter → UPSGroup |
| HAS_UPS_DEVICE | UPS组拥有UPS设备 | UPSGroup → UPSDevice |
| HAS_REMOTE_POWER_PANEL | UPS设备拥有列头柜 | UPSDevice → RemotePowerPanel |
| POWER_SUPPLY | 列头柜供电给机柜 | RemotePowerPanel → Cabinet |
| CONTAINED_IN | 设备在机柜内 | Device → Cabinet |
| CONNECTED_TO | 设备间网络连接 | Device → Device |

## 节点类型总结

| 节点类型 | 描述 | 关键属性 |
|---------|------|----------|
| DataCenter | 数据中心 | name, dc_id |
| Module | 模组 | name, inst_id |
| Building | 楼宇 | name, building_id |
| Room | 房间 | name, room_id |
| Cabinet | 机柜 | name, cabinet_id, height, width, depth |
| UPSGroup | UPS组 | name, group_id |
| UPSDevice | UPS设备 | name, device_id, capacity |
| RemotePowerPanel | 列头柜 | name, panel_id, capacity |
| Device | 设备 | name, device_id, parent_type, ip, role |

## 查询示例

### 基础查询
```cypher
-- 查询模组与数据中心关系
MATCH (m:Module)-[r:BELONGS_TO]->(d:DataCenter)
RETURN m.name, d.name

-- 查询空间拓扑关系
MATCH (dc:DataCenter)-[:CONTAINS]->(b:Building)-[:CONTAINS]->(r:Room)-[:CONTAINS]->(c:Cabinet)
RETURN dc.name, b.name, r.name, c.name

-- 查询电力拓扑关系
MATCH (dc:DataCenter)-[:HAS_UPS_GROUP]->(ug:UPSGroup)-[:HAS_UPS_DEVICE]->(ud:UPSDevice)-[:HAS_REMOTE_POWER_PANEL]->(rpp:RemotePowerPanel)
RETURN dc.name, ug.name, ud.name, rpp.name
```

### 高级查询
```cypher
-- 查询设备故障影响范围
MATCH (failed_device:Device {name: "故障设备"})
MATCH (failed_device)-[:CONNECTED_TO*1..3]-(affected:Device)
RETURN failed_device.name, collect(DISTINCT affected.name) as affected_devices

-- 查询电力故障影响范围
MATCH (failed_rpp:RemotePowerPanel {name: "故障列头柜"})
MATCH (failed_rpp)-[:POWER_SUPPLY]->(affected_cabinet:Cabinet)
MATCH (affected_cabinet)<-[:CONTAINED_IN]-(affected_device:Device)
RETURN failed_rpp.name, collect(DISTINCT affected_cabinet.name) as affected_cabinets, collect(DISTINCT affected_device.name) as affected_devices
```
